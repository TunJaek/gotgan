# 곳간 개발 가이드

라라벨·도커를 처음 만지는 사람이 이 프로젝트를 **열어보고, 찾아가고, 고칠 수 있게** 하는 문서다.
프린팅박스(CodeIgniter)를 기준으로 "이게 거기서 뭐였는지"를 같이 적었다.

---

## 1. 도커 — 컨테이너 2개가 전부다

프린팅박스는 XAMPP처럼 내 PC에 PHP·MySQL을 깔아 쓴다면, 곳간은 그걸 **상자(컨테이너) 안에 넣어** 돌린다.
상자는 딱 2개다.

| 컨테이너 이름 | 정체 | 내 PC에서 접근 |
|---|---|---|
| `gotgan-laravel.test-1` | PHP + 웹서버 | http://localhost:8090 |
| `gotgan-mysql-1` | MySQL 8.4 | `127.0.0.1:3307` |

**중요한 개념 하나** — 소스코드는 상자 안에 복사되는 게 아니라 **내 PC 폴더가 그대로 상자 안에 비친다.**
`C:\workspace\gotgan`을 메모장으로 고치면 상자 안에서도 즉시 바뀐다.
PHP 파일은 고치고 새로고침하면 끝. **재빌드도, 재시작도 필요 없다.**

### 매일 쓰는 명령 4개

```bash
# 켜기 (PC 껐다 켠 뒤)
cd C:\workspace\gotgan
docker compose up -d

# 끄기
docker compose down

# 지금 떠 있는지 확인
docker ps

# 에러 로그 보기 (화면이 하얗게 나올 때)
docker exec gotgan-laravel.test-1 tail -50 storage/logs/laravel.log
```

### 상자 안에서 명령 실행하기

`php artisan ...` 같은 명령은 내 PC가 아니라 **상자 안에서** 돌려야 한다. 앞에 `docker exec gotgan-laravel.test-1`을 붙이면 된다.

```bash
docker exec gotgan-laravel.test-1 php artisan test
```

매번 치기 귀찮으면 PowerShell에서 별칭을 만들어 두면 된다.

```powershell
function art { docker exec gotgan-laravel.test-1 php artisan @args }
# 이후 → art test, art migrate:fresh
```

### 문제가 생겼을 때

| 증상 | 원인 | 해결 |
|---|---|---|
| localhost:8090 접속 안 됨 | 컨테이너가 꺼짐 | `docker compose up -d` |
| 500 에러 / 흰 화면 | PHP 에러 | 위의 `laravel.log` 확인 |
| 파일 고쳤는데 안 바뀜 | 설정 캐시 | `docker exec gotgan-laravel.test-1 php artisan config:clear` |
| DB 접속 안 됨 | MySQL 상자만 꺼짐 | `docker compose up -d` |

> `docker compose down -v`는 **DB 데이터까지 지운다.** `-v` 없이 쓸 것.

## 2. 폴더 지도 — 어디를 고치면 뭐가 바뀌나

프린팅박스와 대응시키면 이렇다.

| 곳간 | 프린팅박스(CI) | 하는 일 |
|---|---|---|
| `routes/web.php` | `application/config/routes.php` | **URL 목록.** 주소와 화면을 연결 |
| `resources/views/components/` | `application/views/` | **화면 + 그 화면의 동작** |
| `app/Models/` | `application/models/` | 테이블 1개 = 클래스 1개 |
| `app/Support/` | `application/libraries/` | 문자 발송, 사업자번호 처리 등 도구 |
| `app/Http/Middleware/` | 컨트롤러의 권한 체크 | 로그인·승인·관리자 확인 |
| `database/migrations/` | (없음. 수동 SQL) | **테이블 설계도.** 아래 4장 참고 |
| `config/gotgan.php` | `application/config/` | 우리 서비스 설정값 |
| `.env` | `database.php` 등 | DB 주소·API 키. **깃에 올리지 않는다** |
| `tests/` | (없음) | 자동 검사 |
| `vendor/`, `storage/`, `bootstrap/` | `system/` | **건드릴 일 없음** |

**컨트롤러 폴더가 왜 텅 비어 있나?** 이 프로젝트는 Livewire라는 방식을 쓴다.
컨트롤러를 따로 두지 않고 **화면 파일 하나에 화면과 동작을 같이 적는다.** 다음 장 참고.

## 3. 화면 파일 읽는 법 (제일 중요)

`resources/views/components/` 안의 `⚡`로 시작하는 파일이 **한 화면**이다.
번개 표시는 "이 파일은 단순 HTML이 아니라 동작도 들어있다"는 표식이다.

예: `resources/views/components/admin/⚡applications.blade.php`

```php
<?php
new class extends Component
{
    public int $tab = 1;                 // ← ① 화면이 기억하는 값 (ApplicationStatus::Reviewing)

    public function with(): array        // ← ② 화면에 넘길 데이터
    {
        return ['applications' => Application::where('status', $this->tab)->get()];
    }
}; ?>
                                          ← ③ 여기부터 아래가 HTML
<div>
    <button wire:click="$set('tab', 3)">승인</button>
    @foreach ($applications as $app)
        {{ $app->business->name }}
    @endforeach
</div>
```

| 부분 | 프린팅박스로 치면 |
|---|---|
| ① `public` 변수 | 화면 상태. `$_SESSION`이나 숨은 input에 담던 값 |
| ② `with()` | 컨트롤러가 `$data`를 만들어 뷰에 넘기던 부분 |
| ③ HTML | 뷰 파일 |
| `wire:click="메서드명"` | 폼 submit / ajax 호출. **JS를 안 쓴다** |

**핵심** — 버튼을 누르면 페이지가 새로고침되는 대신, 저 PHP 클래스의 메서드가 실행되고 바뀐 부분만 다시 그려진다.
JS를 직접 쓸 일이 거의 없다.

### 블레이드(HTML 안의 PHP) 문법 5개

| 쓰는 법 | 뜻 |
|---|---|
| `{{ $name }}` | `<?= htmlspecialchars($name) ?>` (자동 이스케이프) |
| `@if (...)` … `@endif` | `if` |
| `@foreach ($list as $x)` … `@endforeach` | `foreach` |
| `{{-- 주석 --}}` | 화면에 안 나오는 주석 |
| `{{ route('admin.review', $app) }}` | URL 생성. 주소를 직접 쓰지 않는다 |

## 4. 데이터베이스

### DB를 눈으로 보려면

MySQL Workbench에 커넥션을 하나 더 만든다. 프린팅박스와는 **다른 서버**라 기존 커넥션으로는 안 보인다.

| 항목 | 값 |
|---|---|
| Hostname | `127.0.0.1` |
| Port | **3307** (프린팅박스는 3306) |
| Username / Password | `root` / `1234` |
| Default Schema | `gotgan` |

**모든 테이블과 컬럼에 한글 설명이 붙어 있다.** Workbench에서 테이블 우클릭 →
`Table Inspector` → `Columns` 탭의 맨 오른쪽 `Comment` 열에서 볼 수 있다.

쿼리로 한 번에 보려면:

```sql
-- 테이블 설명 전체
SELECT table_name, table_comment
FROM information_schema.tables WHERE table_schema = 'gotgan';

-- 특정 테이블의 컬럼 설명
SELECT column_name, column_type, column_comment
FROM information_schema.columns
WHERE table_schema = 'gotgan' AND table_name = 'posts';
```

### 테이블 이름 규칙

| 규칙 | 예 |
|---|---|
| 기본키는 무조건 `idx` | `posts.idx` |
| 남의 테이블을 가리키면 `대상_idx` | `posts.business_idx` → `businesses.idx` |
| `_id`로 끝나는 건 FK가 **아니다** | `provider_message_id`(문자사 번호). 예외 — `posts.category_id` 는 2026-09-28부터 `categories.idx` FK |
| `created_at` / `updated_at` | 라라벨이 자동으로 채운다. 직접 넣지 말 것 |

### 테이블 구조는 SQL이 아니라 PHP로 바꾼다

프린팅박스는 Workbench에서 `ALTER TABLE`을 직접 쳤지만, 여기서는 **`database/migrations/` 파일을 고치고 명령 한 번**이면 된다.
그래야 코드와 DB가 따로 놀지 않는다.

**개발 중(데이터 버려도 될 때)**

```bash
# migrations 파일을 직접 고친 뒤
docker exec gotgan-laravel.test-1 php artisan migrate:fresh
```

전부 지우고 파일대로 다시 만든다. **데이터가 전부 날아간다.** 지금 단계에서는 이 방법을 쓴다.

**운영 중(데이터를 지키면서)**

```bash
docker exec gotgan-laravel.test-1 php artisan make:migration add_view_count_to_posts
# database/migrations/ 에 새로 생긴 파일을 열어 up() 안에 아래처럼 적고
#   Schema::table('posts', function (Blueprint $table) {
#       $table->unsignedInteger('view_count')->default(0)->comment('조회수');
#   });
docker exec gotgan-laravel.test-1 php artisan migrate
```

> 컬럼을 추가하면 **`->comment('설명')`을 꼭 같이 적는다.** 이 프로젝트의 규칙이다.

### 컬럼을 추가했을 때 같이 고쳐야 할 곳

1. `database/migrations/…` — 컬럼 + `comment()`
2. `app/Models/해당모델.php`의 `$fillable` 배열에 컬럼명 추가
   → **여기 안 넣으면 저장해도 조용히 무시된다.** 가장 흔한 실수다.
3. 날짜·불리언이면 같은 파일 `casts()`에도 추가
4. 상태·종류 컬럼이면 Enum 클래스를 만들고 `casts()`에 연결 (아래 참고)

### 상태·종류 값 규칙 — DB는 숫자, 코드는 Enum

이 프로젝트에는 값 종류를 정하는 규칙이 있다.

| 종류 | 저장 방식 | 예 |
|---|---|---|
| 진짜 예/아니오 | `boolean` (0/1) | `is_hidden`, `price_negotiable`, `success` |
| 역할·상태·종류 | **숫자 + PHP Enum** | `posts.status`, `users.role` |
| 외부 시스템이 준 코드 | 받은 그대로 | `raw_status_code`(국세청), `provider_message_id`(문자사) |
| 바뀔 일 없는 고정 코드 | 숫자 | `region_code` |
| 단계가 있는 분류 | 테이블 + `parent_idx` | `categories` (대·중·소, 최대 3단계) |

**DB에는 숫자만 들어간다.** Workbench에서 보면 `status = 1` 이런 식이다.
뜻은 컬럼 Comment에 적혀 있고, 코드에서는 숫자 대신 이름을 쓴다.

```php
// 나쁜 예 — 3개월 뒤 본인도 못 읽는다
Post::where('status', 1)->get();

// 이 프로젝트 방식
Post::where('status', PostStatus::Selling)->get();   // SQL 에는 1 이 나간다
$post->status->label();                              // 화면에는 "판매중"
```

숫자↔이름 변환은 모델 `casts()`가 알아서 한다. DB에서 꺼내면 이미 Enum 객체다.

#### 전체 매핑표

| 컬럼 | 숫자 | Enum 클래스 |
|---|---|---|
| `users.role` | 0=일반회원 1=운영자 | `UserRole` |
| `users.status` | 0=정상 1=이용정지 | `UserStatus` |
| `businesses.approval_status` | 0=심사중 1=자료보완 2=승인 3=반려 | `ApprovalStatus` |
| `businesses.existence_status` | 0=미조회 1=계속사업자 2=폐업·휴업 | `ExistenceStatus` |
| `applications.status` | 0=작성중 1=심사중 2=보완요청 3=승인 4=반려 | `ApplicationStatus` |
| `application_reviews.decision` | 2=자료보완 3=승인 4=반려 | `ReviewDecision` |
| `notification_logs.type` | 위와 같은 번호 | `ReviewDecision` |
| `existence_checks.result` | 0=조회실패 1=계속사업자 2=폐업 3=휴업 4=미등록 | 아직 없음 |
| `posts.post_type` | 1=팝니다 2=삽니다 | `PostType` |
| `posts.status` | 0=작성중 1=판매중 2=거래완료 3=판매중지 4=보관 | `PostStatus` |
| `posts.condition` | 1=미사용 2=미개봉 3=중고 4=하자 | `PostCondition` |
| `posts.vat_mode` | 1=부가세별도 2=포함 3=협의 | `VatMode` |
| `inquiries.status` | 0=진행중 1=종료 | 아직 없음 |
| `reports.status` | 0=접수 1=확인중 2=조치완료 3=기각 | 아직 없음 |
| `reports.target_type` | 1=매물 2=사업체 3=메시지 | 아직 없음 |

번호를 매기는 원칙은 **0 = 초기·기본 상태**, 그 다음부터 진행 순서다.
`post_type`처럼 "비어있는 상태"가 없는 값만 1부터 시작한다.

`decision`과 `applications.status`는 일부러 같은 번호를 쓴다. 덕분에 변환이 한 줄이다.

```php
ApplicationStatus::from($this->value);   // 2→2, 3→3, 4→4
```

#### Enum 클래스 만드는 법

`app/Enums/` 에 파일 하나. 형식은 전부 똑같다.

```php
<?php

namespace App\Enums;

/** inquiries.status */
enum InquiryStatus: int
{
    case Open = 0;
    case Closed = 1;

    public function label(): string
    {
        return match ($this) {
            self::Open => '진행중',
            self::Closed => '종료',
        };
    }
}
```

만든 뒤 모델 `casts()`에 연결한다.

```php
protected function casts(): array
{
    return ['status' => InquiryStatus::class];
}
```

이러면 `$inquiry->status`가 자동으로 Enum이 된다.

#### 화면에서 쓰는 법

한글 라벨은 **Enum에만 둔다.** 화면마다 배열로 적으면 문구가 갈라진다.

```blade
{{-- 값 하나 표시 --}}
{{ $post->status->label() }}

{{-- 전체를 버튼으로 --}}
@foreach (PostType::cases() as $case)
    <button wire:click="$set('type', {{ $case->value }})">{{ $case->label() }}</button>
@endforeach
```

주의 — Livewire `public` 속성은 Enum을 직접 담을 수 없어서 **숫자로 받는다.**

```php
public int $type = 1;                         // PostType::Sell
// 비교할 때
$type === PostType::Sell->value               // 화면쪽 속성끼리
$post->status === PostStatus::Selling         // 모델 값끼리 (이쪽은 Enum)
```

#### Workbench에서 숫자 대신 한글로 보고 싶을 때

```sql
SELECT idx, title,
       ELT(post_type, '팝니다','삽니다') AS 종류,
       ELT(status+1, '작성중','판매중','거래완료','판매중지','보관') AS 상태
FROM posts;
```

`ELT`는 1부터 세기 때문에 0부터 시작하는 값은 `+1`을 해준다.

## 5. 자주 하는 작업

### 화면 문구만 바꾸고 싶다

`resources/views/components/` 에서 해당 파일을 찾아 한글을 고치고 새로고침. 끝.
어느 파일인지 모르겠으면 문구로 검색하면 된다.

```powershell
Select-String -Path resources\views -Pattern "가입이 승인" -Recurse
```

### 새 페이지를 만들고 싶다

1. `resources/views/components/` 아래에 `⚡이름.blade.php` 생성 (기존 파일 복사가 빠르다)
2. `routes/web.php`에 한 줄 추가

```php
Route::livewire('/posts', 'posts.index')->name('posts.index');
//               ↑ URL      ↑ 파일 위치(components/posts/⚡index.blade.php)
```

`->name()`은 코드에서 `route('posts.index')`로 주소를 부를 때 쓰는 별명이다.

### 접근 권한을 걸고 싶다

`routes/web.php`에서 `middleware`를 붙인다.

| 미들웨어 | 뜻 |
|---|---|
| `auth` | 로그인한 사람만 |
| `approved` | 가입 **승인**된 회원만 (문의·등록·연락처) |
| `admin` | 운영자만 |
| 없음 | 누구나 (목록·검색·상세는 비회원도 봐야 한다) |

### 문자 발송을 테스트하고 싶다

지금은 실제로 안 보내고 로그에만 적는다(`.env`의 `SMS_DRIVER=log`).

```bash
docker exec gotgan-laravel.test-1 tail -30 storage/logs/laravel.log
```

운영 키가 나오면 `.env`를 `SMS_DRIVER=sens`로 바꾸고 `SENS_*` 값을 채우면 코드 수정 없이 실제 발송된다.

### 관리자 계정 만들기

```bash
docker exec -it gotgan-laravel.test-1 php artisan gotgan:admin 000-00-00001 010-0000-0000
```

번호는 **관리자 전용 번호**(사업자번호 검증 규칙을 통과하지 않는 10자리)만 받는다. 개발 환경에서는 비밀번호가 `1234` 로 고정된다. 자세한 내용은 13장.

### 화면을 파일로 떠보기 (브라우저 없이)

```bash
docker exec gotgan-laravel.test-1 php artisan gotgan:snapshot /admin/applications --as=000-00-00001
# storage/app/snapshot.html 에 저장된다
```

## 6. 고치고 나서 — 자동 검사

`tests/` 폴더에 "이건 이렇게 동작해야 한다"가 145개 적혀 있다(2026-09-29). 고친 뒤 한 번 돌리면 뭘 깨뜨렸는지 알려준다.

```bash
docker exec gotgan-laravel.test-1 php artisan test
```

초록 `PASS`면 정상, 빨간 `FAIL`이면 그 아래에 어느 파일 몇 번째 줄이 틀렸는지 나온다.
**코드를 고쳤으면 커밋 전에 반드시 한 번 돌린다.**

검사 항목 예시

## 10. 요청 하나를 끝까지 따라가기

3장이 "화면 파일 한 개를 읽는 법"이라면, 이 장은 **주소를 치고 나서 그 파일까지 어떻게 도달하는지**다.
`http://localhost:8090/` (장터 목록)을 예로 든다.

### 10-1. 첫 요청 — 주소창에 치고 엔터

```
브라우저  GET /
   │
   ▼
public/index.php                    상자 안 모든 요청의 유일한 입구
   │                                (프린팅박스의 index.php와 같은 역할)
   ▼
bootstrap/app.php                   앱을 조립한다. 미들웨어 별칭(approved/admin)이 여기 등록돼 있다
   │
   ▼
routes/web.php:8                    Route::livewire('/', 'posts.index')
   │                                주소 '/' 는 'posts.index' 화면이 담당한다
   │
   ▼
미들웨어                             이 줄은 group 밖에 있어 아무것도 안 걸린다 = 비회원도 통과
   │                                (auth / approved / admin 이 붙는 줄은 아래 표 참고)
   ▼
resources/views/components/posts/⚡index.blade.php
   │
   ├ ① public 속성에 기본값이 들어간다   $keyword='' $type=1 $sort='latest'
   ├ ② with() 가 실행된다               DB 조회 → ['posts' => ...]
   └ ③ ?> 아래 HTML 이 그려진다         @foreach ($posts as $post)
   │
   ▼
resources/views/layouts/app.blade.php      Livewire가 화면을 이 레이아웃으로 감싼다
   │                                       (라우트에 아무것도 안 적어도 자동)
   ▼
resources/views/components/layout.blade.php   <x-layout> — 실제 껍데기
   │                                          <!doctype html>, 헤더, 하단 탭
   ▼
브라우저                              완성된 HTML 한 장
```

**기억할 지점 두 개**

- `⚡` 파일은 `<!doctype html>` 을 적지 않는다. 껍데기는 위 2단이 자동으로 씌운다.
- `⚡` 파일의 HTML은 **반드시 `<div>` 하나로 감싸야 한다.** Livewire가 나중에 이 조각만 교체하려면 바꿀 대상이 하나로 특정돼야 한다.

### 10-2. 두 번째 요청부터 — 검색어를 타이핑했을 때

여기가 프린팅박스와 제일 다른 부분이다. **같은 파일이 다시 실행된다. 페이지 전체가 새로고침되지는 않는다.**

```
[검색어 입력]  wire:model.live.debounce.400ms="keyword"
   │
   ▼
POST /livewire/update                Livewire의 전용 주소. 우리가 만들 일은 없다
   │                                 같이 보내는 것: 지금의 $keyword/$type/$sort + 어느 화면인지
   ▼
같은 ⚡index.blade.php
   │
   ├ ① public 속성이 브라우저가 보낸 값으로 덮인다   $keyword='복사지'
   ├ ② with() 재실행                                 → 조건이 바뀐 새 목록
   └ ③ HTML 재생성
   │
   ▼
브라우저                              바뀐 <div> 조각만 갈아끼운다. 스크롤·입력 포커스 유지
```

같은 경로를 타는 것들:

| 화면에 적힌 것 | 언제 | 무슨 일 |
|---|---|---|
| `wire:model.live="sort"` | 값이 바뀌는 즉시 | `$sort` 갱신 → `with()` 재실행 |
| `wire:model.live.debounce.400ms="keyword"` | 타이핑 멈추고 0.4초 후 | 위와 같음. 글자마다 조회하지 않게 늦춘다 |
| `wire:click="$set('type', 2)"` | 칩 클릭 | `$type` 갱신 → `with()` 재실행 |
| `wire:click="submit"` | 버튼 클릭 | 그 파일의 `submit()` 메서드 실행 |

> **그래서 생기는 함정 하나.** public 속성은 브라우저가 보내온 값으로 덮인다.
> 즉 **화면에 없는 값도 조작해서 보낼 수 있다.** 인증 통과 여부 같은 걸 public 속성에 두면 안 된다.
> (B단계에서 실제로 이 문제로 휴대폰 인증이 우회됐다.)

### 10-3. `with()` 안에서 쓰는 이름의 정체

```php
$this->keyword        이 화면이 기억하는 값 (public 속성)
$keyword              그런 건 없다 → Undefined variable
```

`with()` 안에서는 **속성에 반드시 `$this->` 를 붙인다.** 빼면 흰 화면이 되고 로그에 `Undefined variable` 이 찍힌다.
반대로 `?>` 아래 HTML에서는 `$keyword` 처럼 `$this->` 없이 쓴다. Livewire가 넘겨주기 때문이다.

## 12. 문의 — 만든 방법 (완료)

> 이 장은 문의 기능을 만들 때 쓴 설명서다. 지금 코드는 이대로 완성되어 있다. 문의 기능을 고칠 때 흐름을 이해하는 용도로 읽는다.

HTML 을 먼저 짜 두고 PHP 를 채우는 순서로 만들었다. 화면은 세 곳이다.

| 파일 | 역할 |
|---|---|
| `⚡detail.blade.php` | `문의하기` 버튼 + 모달 (기존 파일에 추가됨) |
| `resources/views/components/inquiries/⚡index.blade.php` | 문의함 |
| `resources/views/components/inquiries/⚡chat.blade.php` | 대화 |
| `layout.blade.php` | 헤더·하단탭 안 읽음 배지 |

각 파일 맨 위 주석에 **"이 마크업이 기대하는 값"** 이 적혀 있다. 그 이름과 모양을 맞추면 된다.

### 12-1. 먼저 스키마를 바꾼다

지금 `inquiries` 는 **(매물 + 사람 한 쌍)** 이 한 방이다. **사람 한 쌍**이 한 방이 되도록 바꾼다.
그러면 한 방에 여러 매물 얘기가 섞이므로, 매물 정보는 방이 아니라 **메시지**로 내려가야 한다.

`database/migrations/2026_09_16_000300_create_ops_tables.php` 를 고친다.

**`inquiries` 에서 뺄 것**

```php
$table->unsignedInteger('post_idx')...      // 삭제
$table->json('terms_snapshot')...           // 삭제
$table->foreign('post_idx')...              // 삭제
```

**`inquiries` 에서 바꿀 것** — `from_user_idx` / `to_user_idx` 는 "누가 먼저 열었나" 로 뜻이 바뀐다.
주석만 고치면 되고 컬럼명은 그대로 둬도 된다. 대신 **같은 쌍이 방을 두 개 만들지 못하게** 막는다.

```php
$table->unique(['from_user_idx', 'to_user_idx']);
```

> 이것만으로는 A→B 방과 B→A 방이 따로 생기는 것을 못 막는다. 방을 찾을 때
> **양방향으로 찾아야 한다**(12-3 참고). DB 로 완전히 막으려면 항상 작은 번호를
> `from` 에 넣는 규칙이 필요한데, 그러면 "누가 먼저 열었나" 를 잃는다. 찾을 때 양방향으로 보는 쪽이 낫다.

**`messages` 에 더할 것**

```php
$table->unsignedInteger('post_idx')->nullable()->after('sender_idx')
    ->comment('이 메시지가 어느 매물 얘기로 시작했는지. 일반 대화는 NULL');
$table->json('terms_snapshot')->nullable()->after('post_idx')
    ->comment('문의 시점의 가격·조건 사본. 글이 바뀌어도 대화 맥락이 남는다');

$table->foreign('post_idx')->references('idx')->on('posts')->nullOnDelete();
```

`nullOnDelete()` 를 쓰는 이유 — 매물이 지워져도 **대화는 남아야 한다**. `cascadeOnDelete()` 면
메시지까지 같이 사라진다.

고친 뒤 `php artisan migrate:fresh --seed` 로 다시 만든다.

### 12-2. 모델 둘

**`app/Models/Inquiry.php`** (새로 만든다)

- `$primaryKey = 'idx'`, `$fillable` 에 `from_user_idx`, `to_user_idx`, `status`, `last_message_at`
- `casts()` 에 `'last_message_at' => 'datetime'`, `'status' => InquiryStatus::class`(enum 을 만들지, 그냥 숫자로 둘지는 판단)
- `messages()` — `hasMany(Message::class, 'inquiry_idx')`
- **`partner()`** — 상대를 꺼낸다. 관계가 아니라 **메서드**여야 한다. 내가 `from` 일 수도 `to` 일 수도 있어서
  관계 하나로는 못 고른다.
  ```php
  public function partner(): User   // 대략 이런 모양
  ```
  마크업은 `$room->partner->company_name` 으로 읽는다. **속성처럼 쓰므로 접근자(accessor)로 만드는 게 편하다** —
  `getPartnerAttribute()` 로 만들면 `$room->partner` 가 된다.

**`app/Models/Message.php`** (새로 만든다)

- `$fillable` 에 `inquiry_idx`, `sender_idx`, `body`, `post_idx`, `terms_snapshot`, `read_at`
- `casts()` 에 `'terms_snapshot' => 'array'`, `'read_at' => 'datetime'`
- `post()` — `belongsTo(Post::class, 'post_idx')`

**`User`** 에 더할 것

- `unreadInquiryCount(): int` — 헤더 배지가 부른다. **사람 수**다(메시지 수가 아니다).
  "내가 받는 쪽인 메시지 중 `read_at` 이 NULL 인 것" 을 방 단위로 센다.
  ```
  안 읽은 메시지가 있는 방 중, 내가 to 인 것 → 나에게 온 문의
  ```
- `unreadReplyCount(): int` — 문의함 위쪽 알림. 위와 같은데 **내가 from** 인 경우다.

> 둘을 가르는 기준은 **누가 방을 먼저 열었나**다. 내가 `from` 이면 내가 말을 건 방(보낸 문의),
> `to` 면 상대가 건 방(받은 문의)이다. 컬럼이 이미 있으므로 SQL 에서 바로 걸린다.
>
> 처음에는 이 기준을 **마지막 매물 주인**(`post.user_idx`)으로 잡았다. 매물 표시를 화면에서
> 빼면서 사용자 눈에 안 보이는 값으로 가르는 셈이 되어 `from`/`to` 로 옮겼다. 매물 카드를
> 되살릴 때 매물 주인 기준이 다시 필요하면 그때 바꾸면 된다.

### 12-3. 방을 찾거나 만드는 규칙

문의를 보낼 때마다 쓰는 핵심 로직이다. **한 군데에 두고 모두가 그것만 부르게 한다.**
(오늘 초안 쿼리가 두 군데에 흩어져 한쪽만 고쳐 사고가 났다. 같은 실수를 반복하지 않는다.)

`Inquiry` 에 정적 메서드 하나를 둔다.

```php
public static function between(User $a, User $b): self
```

안에서 할 일

1. **양방향으로 찾는다** — `(from=A and to=B)` 또는 `(from=B and to=A)`
2. 없으면 만든다. 이때 `from` 은 **지금 말을 거는 사람**
3. 있으면 그대로 돌려준다

자기 자신에게는 방을 만들 수 없다. `$a->idx === $b->idx` 면 막는다.

### 12-4. `⚡detail.blade.php` 에 더할 것

마크업이 부르는 이름은 이미 정해져 있다.

| 이름 | 종류 | 설명 |
|---|---|---|
| `$inquiry_open` | `#[Locked] public bool` | 모달 표시 여부 |
| `$inquiry_message` | `public string` | 첫 메시지 본문 |
| `openInquiry()` | 메서드 | 비회원 → 로그인, 미승인 → 가입 현황, 자기 글이면 막기 |
| `closeInquiry()` | 메서드 | 닫고 입력·에러 비우기 |
| `sendInquiry()` | 메서드 | 검증 → 방 찾기/만들기 → 메시지 저장 → 대화로 이동 |

`sendInquiry()` 안에서

- **권한을 다시 확인한다.** 모달이 화면에 없어도 요청은 보낼 수 있다(`openReport()`/`report()` 와 같은 이유)
- **자기 글에는 문의할 수 없다** — `abort_if($this->isMine(), 403)`
- 검증: `['required', 'min:5', 'max:1000']`
- `terms_snapshot` 은 **지금 값을 그대로 박는다**
  ```php
  ['price' => $post->price_amount, 'vat' => $post->vat_mode?->label(), 'status' => $post->status->name]
  ```
- 메시지 저장과 `inquiries.last_message_at` 갱신을 **한 트랜잭션에** 묶는다
- 끝나면 `redirectRoute('inquiries.show', $room)`

`lang/ko/validation.php` 의 `attributes` 에 `'inquiry_message' => '문의 내용'` 을 더한다.

### 12-5. 문의함 컴포넌트

**받은 문의 / 보낸 문의 두 탭이다.** 속성 하나가 필요하다.

```php
public string $tab = 'received';     // 'received' | 'sent'
```

마크업은 `wire:click="$set('tab', 'sent')"` 로 값만 바꾼다. 메서드를 따로 만들 필요는 없다.
**거르는 일은 `with()` 에서 한다** — 마크업은 이미 걸러진 `$rooms` 만 받는다.

`with()` 가 넘길 것은 `$rooms` 와 `$reply_count` 둘이다.

`$rooms` 를 만들 때

- **탭에 따라 방향을 거른다.** 기준은 **누가 방을 먼저 열었나**다
  - `received` → `to_user_idx` 가 나인 방 (상대가 말을 걸어온 방)
  - `sent` → `from_user_idx` 가 나인 방 (내가 말을 건 방)
- `last_message_at` 내림차순
- `with(['from', 'to', 'lastMessage'])` 로 상대 업체명과 마지막 메시지를 미리 불러온다.
  안 그러면 방마다 쿼리가 나간다(N+1)
- `unread_count` 는 `withCount()` 로 붙인다 — 방마다 세지 않고 한 번에 나간다

`$reply_count` 는 **보낸 문의 탭에서만** 쓴다. 받은 문의 탭에서는 헤더 말풍선 배지가 같은 역할을 한다.

> 마크업은 `$room->partner`, `$room->unread_count` 처럼 **속성으로** 읽는다.
> `partner` 는 모델 접근자, `unread_count` 는 `withCount()` 가 붙여주는 값이다.

### 12-6. 대화 컴포넌트

| 이름 | 종류 | 설명 |
|---|---|---|
| `$room` | `public Inquiry` | 라우트에서 들어온다 |
| `$draft` | `public string` | 입력칸 |
| `send()` | 메서드 | 검증 → 저장 → `last_message_at` 갱신 → `$draft` 비우기 |
| `markAsRead()` | 메서드 | 상대가 보낸 안 읽은 메시지의 `read_at` 을 채운다 |

**`mount()` 에서 두 가지를 한다.**

1. **내 방인지 확인** — `abort_unless` 로 `from`/`to` 중 하나가 나인지 본다. 남의 대화를 주소로 열 수 없어야 한다
2. **읽음 처리 한 번** — `markAsRead()` 를 부른다

#### 읽음 처리를 어디에 둘 것인가

셋 중에 고르게 된다.

| 두는 곳 | 언제 도는가 | 문제 |
|---|---|---|
| `mount()` 만 | 진입 시 1회 | 열어둔 채 새 메시지를 받으면 읽음이 안 찍혀 헤더 배지가 남는다 |
| `with()` 안 | 재렌더링마다 | 입력·정렬 등 아무 때나 같이 돌아서 **쓰기가 일어나는 줄 모른다** |
| **액션으로 분리** | 폴링이 부를 때 | — |

**액션으로 분리하는 쪽을 쓴다.** `markAsRead()` 를 `public` 으로 두고 마크업에서 직접 부른다.

```blade
<div class="narrow" wire:poll.30s="markAsRead">
```

`mount()` 에서도 한 번 부르는 이유 — 폴링은 30초 뒤에야 처음 돈다. 그사이 대화를 보고 있는데도
배지가 남는다.

> **0건 UPDATE 를 걱정하지 않아도 된다.** 조건이 `WHERE` 에 있으므로 털 것이 없으면
> 0건 갱신으로 끝난다. 이걸 피하려고 `exists()` 로 먼저 확인하면 `SELECT` 만 한 번 더 는다.

> **`.visible` 을 붙일지는 따로 판단한다.** `wire:poll.visible.30s` 로 하면 다른 탭에 가 있는 동안
> 읽음이 안 찍혀 정확해지지만, 새 메시지도 같이 안 들어온다. 지금은 안 붙였다.

> **웹소켓은 아직 이르다.** Reverb 를 띄우면 상시 프로세스가 하나 늘고 배포·인증·재연결이 따라온다.
> 지금 아쉬운 건 "최대 30초 늦게 뜬다" 하나뿐이다. 사용자가 늦다고 말하거나 푸시 알림을 붙일 때
> 그때 가서 올린다.

`markAsRead()` 가 `public` 이 되면 화면 없이도 호출할 수 있다. `mount()` 뿐 아니라
**이 메서드 안에서도 내 방인지 다시 본다**. `send()` 와 같은 이유다(`openReport()`/`report()` 참고).
세 곳이 같은 확인을 하므로 `assertInRoom()` 같은 private 메서드로 묶는다.

`send()` 는 `sendInquiry()` 와 거의 같다. 다른 점은 매물 카드를 붙이지 않는다는 것뿐이다
(`post_idx`·`terms_snapshot` 은 NULL).

## 13. 운영 서버에 올리기 전 점검표

코드가 아니라 **운영 서버의 `.env`** 에서 바꾸는 것들이다. 로컬 `.env` 는 그대로 둔다.

| 항목 | 로컬(지금) | 운영 서버 | 안 바꾸면 |
|---|---|---|---|
| `APP_ENV` | `local` | `production` | https 강제(`AppServiceProvider`)가 켜지지 않는다 |
| `APP_DEBUG` | `true` | `false` | 오류 화면에 코드·설정값·DB 정보가 그대로 보인다 |
| `APP_URL` | `http://192.168.0.80:8090` | `https://실제주소` | 링크·리다이렉트 주소가 내부 IP 로 나간다 |
| `APP_KEY` | 로컬용 | 운영 서버에서 `php artisan key:generate` 로 새로 | 로컬 키가 새면 세션·암호화 값이 같이 뚫린다 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / `1234` | 곳간 DB 에만 권한 있는 전용 계정 | 앱이 뚫리면 서버의 모든 DB 가 같이 뚫린다 |
| `SESSION_SECURE_COOKIE` | 없음 | `true` | 로그인 쿠키가 http 로도 오간다 |
| `SMS_DRIVER` | `log` | `sens` + `SENS_*` 키 | 심사 결과·변경 안내 문자가 실제로 안 나간다 |
| `PASS_DRIVER` | `log` (지금은 실제 화면 확인용으로 `danal`. **인증할 때마다 요금이 나갈 수 있다**) | `danal` + `DANAL_CPID`·`DANAL_CPPWD` | 다날 대신 개발용 가짜 인증 화면이 나온다. **운영에서 `log` 면 아무나 아무 번호로 인증된다** |
| `BIZNO_DRIVER` | `log` | `nts` + `BIZNO_API_KEY` | 가입·존속 점검이 형식 검사만 한다 |

`BIZNO_API_KEY` 에는 공공데이터포털 → 마이페이지 → 활용신청 상세의 **'일반 인증키'** 를 그대로 넣는다. `%2F`·`%3D` 가 섞인 형태여도 `BiznoStatus` 가 풀어서 쓴다.

### 관리자 계정 만들기

관리자는 **관리자 전용 번호**로 만든다. 사업자번호 검증 규칙을 통과하지 않는 10자리(예: `000-00-00001`)라 실제 사업자와 겹치지 않고, 가입 화면에서 누구도 그 번호로 가입할 수 없다. 실제 사업자번호를 관리자에 쓰면 그 사업자는 회원으로 가입할 수 없다.

```bash
# 운영 서버: 비밀번호를 화면에 보이지 않게 두 번 묻는다(회원과 같은 규칙). 개발(APP_ENV=local): 1234 로 고정
# 휴대폰은 정보 수정 본인인증에 쓰이니 본인 번호를 넣는다
docker exec -it gotgan-laravel.test-1 php artisan gotgan:admin 000-00-00001 010-0000-0000
```

- 관리자도 회원 기능(매물 등록·문의·연락처 보기·관심 표시·신고)을 모두 쓸 수 있다(2026-09-30). 연락처 보기·문의의 하루 한도만 적용하지 않고, 열람 기록은 똑같이 남는다. 탈퇴는 할 수 없다.
- 관리자 화면은 헤더에 링크가 없다. `/admin` 을 직접 친다.
- 회원 화면의 "운영자에게 문의" 안내는 `/admin/users/{번호}` 에서 처리한다: 상호·대표자명 변경, 휴대폰·본인인증 초기화, 탈퇴 처리(모두 사유 필수, 조치 기록에 남음).

### 매일 도는 작업 (cron)

보유기간이 지난 기록을 지우는 `app:purge` 가 매일 04:00 에 돈다(`routes/console.php`). 서버 cron 에 이 한 줄이 있어야 실제로 돈다.

```
* * * * * cd /곳간/경로 && php artisan schedule:run >> /dev/null 2>&1
```

처음에는 지우지 않고 몇 건이 지워질지만 본다.

```bash
docker exec gotgan-laravel.test-1 php artisan app:purge --dry-run
```

| 기간 | 대상 |
|---|---|
| 90일 | 반려 신청 개인정보, 사업자등록증 원본(승인 후), 탈퇴 회원 매물, 연락처 열람 기록, 철회한 연락처 동의, 처리 끝난 신고, 가입 심사 기록, 존속 점검 기록, 문자 발송 기록 |
| 1년 | 대화방(마지막 메시지 기준), 운영자 조치 기록 |

기간을 바꾸면 `Purge.php` 의 숫자와 `resources/legal/privacy-v1.md` 를 같이 고친다.

### 사업자 존속 점검

지금은 사람이 돌린다. 스케줄·자동 숨김은 출시 후에 붙인다.

```bash
docker exec gotgan-laravel.test-1 php artisan app:business-check            # 승인 회원 전체
docker exec gotgan-laravel.test-1 php artisan app:business-check --limit=3  # 앞에서 3명만
```

결과는 관리자 → 존속 점검 화면(`/admin/existence-checks`)에서 본다. **조회 실패는 폐업이 아니다.** 키 누락·통신 오류는 '조회 실패'로 따로 남는다.
